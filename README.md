# Motion Detector

Готовый учебный проект для обнаружения движения и подсчёта пересечений стоп-линии на CPU. Используются классические объяснимые методы: GaussianBlur, MOG2/KNN/разность кадров/running average, морфология, контуры, ROI, centroid tracking и геометрия пересечения линии. Нейросетевая обучающая выборка не требуется.

## Запуск за пару минут

Требуются Python 3.10+, NumPy и OpenCV. Перейдите в каталог проекта:

```powershell
cd motion_detector
python -m pip install -r requirements.txt
python scripts/generate_demo.py
python main.py --video data/demo.mp4 --config configs/demo.json --headless --output results/demo.mp4 --events results/events.jsonl --statistics results/statistics.csv
```

В Windows PowerShell можно добавить `--snapshot-every 60` и `--snapshot-dir outputs/motion_detector/results/snapshots`. Интерактивное окно включено по умолчанию: **q/Esc** — выход, **s** — сохранить текущий диагностический кадр. Для веб-камеры: `--video 0`. Для одной панели вместо коллажа: `--output-view overlay`.

Можно обработать все ролики из каталога одной командой. Параметр `--video` принимает каталог и ищет в нём `.avi` (а также `.mp4`, `.mkv`, `.mov`, `.m4v`) рекурсивно. Для текущего набора `data/video` можно использовать короткое имя `videos`: если такой папки нет, оно автоматически перенаправляется в `data/video`.

```powershell
python main.py --video videos --config configs/demo.json --headless `
  --events-dir results/events --statistics-dir results/statistics --output-dir results/videos
```

Для проверки на части набора добавьте `--limit-videos 10`. Каждый результат получает имя исходного файла, поэтому весь набор обрабатывается последовательно и не требует загрузки всех роликов в память.

Предупреждение `ext header missing` относится к старому кодеку MPEG-4 внутри AVI. Если нужен тихий повторный запуск, можно один раз создать MP4-копии, не удаляя исходные файлы:

```powershell
python scripts/convert_videos.py --input videos --output videos_mp4
python main.py --video videos_mp4 --config configs/demo.json --headless `
  --events-dir results/events --statistics-dir results/statistics --output-dir results/videos
```

Во время пакетной обработки консоль показывает номер и имя текущего файла. Для просмотра роликов в GUI на скорости источника уберите `--headless` и добавьте `--playback`; без `--playback` окно показывает кадры с максимальной скоростью обработки. Конвертер использует встроенный OpenCV, продолжает работу после ошибки одного файла и сохраняет список ошибок в итоговом JSON.

Ожидаемое событие в JSONL: один `line_crossing` с `track_id`, кадром, временем, координатой и направлением. У тестового клипа результат обычно около 1 события, однако он зависит от версии OpenCV и параметров.

## Пороговая линия и тревоги

Без поля `line` в конфиге система сигнализирует о подтверждённом движении в ROI. Если указать два конца `line`, событие возникает при переходе отслеживаемого центра объекта через конечный отрезок. Трекинг использует ближайший центр, направление и гистерезис; новый объект сначала получает устойчивую сторону и должен продержаться `tracker_min_hits` кадров. Для однонаправленного потока можно выбрать `direction`: `both`, `neg_to_pos` или `pos_to_neg`. Перестановка концов линии меняет названия направлений.

Координаты ROI и линии заданы в пикселях исходного кадра. Все вершины должны попадать внутрь изображения. `warmup_frames` исключает начальное обучение фона, а `illumination_guard` временно переобучает модель после общей резкой вспышки/смены света. Для неизвестной сцены проверяйте её с выключенной и включённой защитой.

## Методы и настройка

`mog2` и `knn` — адаптивные модели фона (`mog2` включён по умолчанию); `knn` — сравнение на множестве соседей; `diff` — изменения между соседними кадрами; `running_average` — фон с экспоненциальным обновлением. Метод меняется флагом `--method`. Параметры находятся в `configs/demo.json`; CLI может переопределить основные настройки. Полный набор примерных значений можно сохранить через `--save-config path.json`.

Здесь `blur_kernel` и `morphology_kernel` должны быть положительными нечётными числами. `min_area` — площадь контура в пикселях². `shadow_threshold` отбрасывает значения MOG2 ниже порога (обычно тень OpenCV имеет значение 127). Opening удаляет мелкие шумовые области, closing заполняет дырки, dilate слегка соединяет пиксели перед контурным анализом. Уменьшайте `learning_rate`, если люди двигаются медленно или надолго останавливаются. Разрешение и масштаб видео требуют подстройки площади и максимального расстояния трекера.

## Сравнение и данные

Сгенерировать тестовое видео (по умолчанию 240 кадров) и покадровые PNG-маски без скачиваний: `python motion_detector/scripts/generate_demo.py`. Запустить одинаковый production-конвейер для всех четырёх методов:

```powershell
python evaluation/run_benchmark.py --video data/demo.mp4 --config configs/demo.json --ground-truth-dir data/demo_ground_truth --event-times 4.08 --output results/benchmark.csv
python scripts/summarize_benchmark.py --input results/benchmark.csv --markdown results/demo_benchmark.md --plot results/benchmark.png
```

Для synthetic-ролика мы знаем номинальное время прохода: `--event-times 4.08` позволяет оценить задержку/ложные события с допуском 1 секунду. Результаты содержат FPS, кадровые precision/recall/F1 («есть объект»), агрегированные пиксельные precision/recall/F1/IoU, средний IoU кадра и число событий. Метрики ложных тревог и задержки доступны с разметкой времён прохода, например `--event-times 1.44`, иначе они намеренно не выдаются. Для CDnet сопоставьте имена/номера PNG-масок и заранее преобразуйте классы движения в бинарные маски: в ground truth могут быть дополнительные классы тени/unknown.

Синтетическое видео удобно для проверки установки, корректности экспорта и ожидаемого пересечения, но не является доказательством точности в реальном наблюдении. Для защиты добавьте PETS/CDnet или свои ролики для дня, ночи, фар и динамического фона; используйте ручную покадровую разметку и указывайте видео, освещение, FPS и параметры. Одно короткое видео даёт лишь демонстрационные, не обобщаемые FPS/метрики.

## Проверка проекта

```powershell
python -m unittest discover -s tests -v
```

Пакет поддерживает `python -m motion_detector ...` после установки. Для editable install из корня репозитория: `python -m pip install -e outputs/motion_detector`.

## Структура

```text
motion_detector/
├── main.py, config.py, visualization.py
├── detector/   # фон, фильтрация, ROI, тревога, трекинг, линия, общий конвейер
├── evaluation/ # сегментация/FPS/события и benchmark
├── scripts/    # генератор тестового ролика и масок
├── configs/    # пример ROI/stop-line
├── data/       # демо-видео, разметка и .gitignore больших внешних данных
├── results/    # пример CSV и воспроизводимый отчёт benchmark
├── report/     # план экспериментов и шаблон отчёта
└── tests/      # unittest, включая полный запуск CLI и сохранение видео
```
